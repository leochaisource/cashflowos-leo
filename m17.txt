feat(pm): seven new projects and a next-steps layer across dashboard, briefs, bot

TWO KINDS OF PROJECT, TWO HOMES. An ad client needs code config (env var names,
lead action types, keywords), so Starcity Global joins lib/ad-clients.ts —
skipped by every cron until its two env vars exist, so it costs nothing while
credentials are pending. A work project — "fix Dr Tariq's malware by Tuesday" —
needs only a name, a status, a deadline and next steps: that is a `records` row,
so the five new ones (Mr Money Academy, Dr Tariq, Sandra, Trisen Markethon,
Firstin5) live there, with lib/work-projects.ts as the pure-function lens over
rows every consumer already fetches.

THE MINI-PM LAYER, one convention end to end: a next step is a task row whose
meta.project holds either kind of id — the same convention receipts already use.
- Every project page (ad or work) gets a Next Steps band: add with a deadline,
  tick off, reopen. Ticking flips status; nothing is deleted.
- Home shows the plate: per-ad-client step counts on the cards, and a Work
  Projects table with phase, target date and the next step, overdue in rust.
- Work projects get their own page at /projects/<slug> — target countdown,
  steps, and any receipts tagged to them.
- The 9am daily brief gains "On your plate": every project's open steps,
  overdue first and bolded. The 8am per-client brief feeds the owner's steps to
  the model with orders that its 3 actions START from overdue/due-soon items and
  never invent a deadline.
- Bot add_task takes an optional project; captions and typed expenses can now
  tag work projects too ("Dr Tariq — hosting invoice" → dr-tariq-website),
  verified alongside the demo-switch rule (hidden demo clients stay unmatchable).

Verified against live data: 5 work projects render with correct summaries, the
plate sorts Mr Money Academy's meeting as "due tomorrow" and Dr Tariq as "due in
2d", and caption matching resolves all three new-name tests.
